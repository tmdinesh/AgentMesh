### Phase 4 – Scalability Check  

**1. Horizontal vs. Vertical Scalability Analysis**  
- **Stateless Services:** The Node.js API Gateway and Spring Boot microservices are designed as stateless containers running on Kubernetes, allowing seamless horizontal autoscaling via Horizontal Pod Autoscalers (HPA) based on CPU and memory thresholds.  
- **Stateful Components (Bottlenecks):**  
  - **PostgreSQL Database:** Currently a single primary node handling both reads and writes. While read replicas exist, write scalability is vertically constrained by hardware limits and locking contention during high transaction volumes.  
  - **Redis Cache Cluster:** Configured as a single standalone instance. Under heavy load, memory exhaustion and high connection pooling thresholds risk causing cluster-wide cache failures.  

**2. Distributed Data Management & Partitioning**  
- **Sharding Strategy:** The monolithic tables (`orders` and `transactions`) lack horizontal partitioning. Implementing range/hash-based table partitioning on `created_at` and `user_id` is essential to maintain query performance as data size grows into the terabytes.  
- **Eventual Consistency & Messaging:** Transitioning synchronous inter-service communication (identified in Phase 1 and 3) to an asynchronous message broker (such as Kafka or RabbitMQ) will decouple the services, ensuring that traffic spikes in one domain do not cause cascading failures across the entire ecosystem.  

**3. Autoscaling Policies & Load Balancing**  
- **K8s HPA Configuration:** Refine HPA rules to trigger scaling actions based on custom metrics (e.g., consumer lag in the message queue, incoming request rates) rather than static CPU metrics alone.  
- **Traffic Routing:** Ensure Layer 7 load balancers use intelligent least-connection algorithms and enforce robust rate-limiting policies at the edge to mitigate unexpected traffic surges or DDoS events.  

**4. Scalability Recommendations**  
- Implement PostgreSQL database sharding/partitioning and promote read replicas for heavy reporting queries.  
- Migrate Redis from a single-node setup to a Redis Cluster architecture with master-replica replication and automated failover.  
- Adopt an event-driven architecture using Kafka for high-throughput, asynchronous inter-service communication.

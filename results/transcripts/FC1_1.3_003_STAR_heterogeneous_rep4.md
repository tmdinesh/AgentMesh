- **Auth flow weaknesses** – no MFA, limited session controls.

### 3. Performance Bottlenecks  
- **Database connection‑pool exhaustion** – fixed pool size and long‑running queries cause thread blocking under load.  
- **Inefficient caching** – Redis lacks TTL/eviction and proper invalidation, leading to memory bloat and stale reads, increasing latency.

### 4. Scalability Recommendation  
Implement a **CQRS + Event‑Driven Replication** pattern with **horizontal sharding** of the transactional database.  
- Write side remains on the primary DB; read side is served by replicated/derived stores updated asynchronously via RabbitMQ.  
- Sharding distributes write load, eliminating the connection‑pool contention identified in the performance analysis.  
- Asynchronous reads reduce gateway pressure, mitigating the insecure gateway risk.

#### **Phase 1: Design Audit – Key Findings**  
- **Strengths:**  
  - Clear separation of concerns via microservices; well-defined API contracts using OpenAPI.  
  - Use of Docker and Kubernetes (EKS) enables consistent deployment and environment parity.  
- **Weaknesses:**  
  - Some microservices retain local state, undermining true horizontal scalability.  
  - Inconsistent service boundaries lead to duplicated logic and coupling in data access layers.  
- **Recommendation:**  
  - Enforce stateless design across all services.  
  - Conduct a service boundary audit to eliminate cross-cutting concerns and enforce domain-driven design (DDD) principles.

---

#### **Phase 2: Security Analysis – Key Findings**  
- **Strengths:**  
  - TLS enforced at ingress (via AWS ALB) and in-transit encryption for all internal services.  
  - Secrets managed via AWS Secrets Manager with automated rotation.  
- **Weaknesses:**  
  - Inconsistent authentication/authorization across services—some use JWTs, others rely on session cookies without short-lived tokens.  
  - No runtime policy enforcement (e.g., Istio or OPA) for service-to-service access control.  
  - Legacy services expose endpoints without rate-limiting or IP whitelisting.  
- **Recommendation:**  
  - Implement a service mesh (e.g., Istio) with mutual TLS and fine-grained access policies.  
  - Enforce OAuth2.0 with short-lived tokens and enforce RBAC at the API gateway level.  
  - Apply rate limiting and IP filtering at ingress using WAF or API Gateway.
